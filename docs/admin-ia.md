# 管理后台信息架构与需求对齐

> 跨对话需求基线。实现或改菜单/能力时以本文为准；有变更请同步改本文并注明日期。
>
> 最后更新：2026-08-07

## 1. 产品前提

| 项 | 约定 |
|----|------|
| 技术挂载 | `apps/admin`（Vue3 + Vite + **Element Plus**）；API 为 Cloudflare Workers + Hono |
| 分类 / 标签 | **进入 C 端筛选**；后台删分类/标签前需处理壁纸引用 |
| 壁纸发布 | **必须审核**；仅「已上架」且原图就绪才对 C 端可见/可下载 |
| 权益变更 | 手工续费、开通、改到期等 **必须记入订单**（可为 0 元单） |
| 价目来源 | 会员售价以「会员档位与价目」为唯一配置源，不写在基础网站配置里 |
| 布局壳 | 双栏导航（一级图标栏 + 二级文字栏）+ 顶栏，见 §2 |
| 权限 | 角色配置 **菜单 + 页面按钮 + 默认数据范围**；管理员可覆盖数据权限，见 §5 |

## 2. 整体布局壳

参考示意：[`assets/admin-layout-ref.png`](./assets/admin-layout-ref.png)

### 2.1 区域划分

```text
┌─────────────────────────────────────────────────────────┐
│  A  顶栏：消息 + 管理员信息（可含品牌/快捷入口）           │
├─────┬───────────────────────────────────────────────────┤
│     │  D  中主体                                         │
│  B  │  ┌──────────┬──────────────────────────────────┐  │
│  大 │  │ E 二级菜单 │  F 内容主体                        │  │
│  主 │  │（随 C 切换）│  （列表 / 表单 / 占位页）            │  │
│  体 │  │            │                                    │  │
│     │  └──────────┴──────────────────────────────────┘  │
│  ┌──┤                                                   │
│  │C │  一级菜单（图标 + 文案）                            │
│  │  │                                                   │
│  └──┴───────────────────────────────────────────────────┘
└─────────────────────────────────────────────────────────┘
```

| 区 | 名称 | 职责 |
|----|------|------|
| **整页底** | 渐变背景 | **左上 → 右下** 渐变；A/C/E/F 面板叠在渐变之上（面板可用半透明/白底卡片，不要让整页死白一块） |
| **A** | 顶栏 | 消息（可先占位铃铛）；当前管理员信息（邮箱/昵称、退出）；可选站点名 |
| **B** | 大主体 | A 以下全部；左右分为 C + D |
| **C** | 一级菜单 | 对应菜单树 **1–6 顶级**；竖向图标 + 短文案；选中高亮后切换 E |
| **D** | 中主体 | C 右侧；左右分为 E + F |
| **E** | 二级菜单 | 当前一级下的子项（如壁纸资源 → 列表/分类/标签/下载记录）；选中项高亮 |
| **F** | 内容主体 | 页面标题 + 筛选/操作 + 表格或表单或占位空态 |

### 2.2 与菜单映射

| C 一级 | E 二级 |
|--------|--------|
| 首页看板 | 数据总览 |
| 用户会员 | 用户列表、黑名单管理 |
| 壁纸资源 | 壁纸列表、分类管理、标签管理、下载记录 |
| 订单财务 | 全部订单、财务统计 |
| 站点设置 | 基础网站配置、会员档位与价目、公告管理、**员工管理**、角色管理 |
| 系统工具 | Cloudflare、存储 R2、Resend、虎皮椒、全局操作日志、定时任务监控 |

### 2.3 交互与视觉约定

- **C 切换**：只换 E 的菜单组与默认落地二级页（该组第一项，或该组上次访问项）。
- **E 点击**：只换 F 内容与路由，C 保持选中。
- **仅一项二级时**（如首页只有「数据总览」）：E 仍保留，避免布局在「有无二级」间跳动。
- **F 内**：内容放在圆角面板/卡片上；列表页顶栏放标题 + 主操作（如「上传壁纸」）；筛选条与表格分区清晰。
- **A 消息**：P0 可只做入口占位，不接真实消息中心。
- **响应式**：P0 以桌面宽屏为主；窄屏策略（收起 E / C 变抽屉）可后定，不挡主流程。

### 2.4 实现提示（apps/admin）

- 壳组件建议：`AdminLayout` = A + B；`PrimaryNav` = C；`SecondaryNav` = E；`<router-view>` 落在 F。
- 一级/二级与路由的对应关系以 §3 菜单树与路径表为准。

## 4. 模块能力

### 4.1 首页看板

| 页 | 状态 | 说明 |
|----|------|------|
| 1.1 数据总览 | 占位 | 后续可接：用户数、付费会员、今日订单、待审壁纸、下载次数 |

### 4.2 用户会员

#### 2.1 用户列表

- 基础信息展示
- 编辑资料
- 查看该用户维度操作日志
- 手动续费 / 开通会员（**出订单**）
- 账号禁用 / 解封

顶部筛选：

- 付费会员 / 免费用户
- 注册时间
- 是否拉黑

#### 2.2 黑名单管理

- 拉黑 / 解除拉黑

#### 账号状态约定

| 能力 | 含义 |
|------|------|
| **禁用** | 不能登录 C 端；关联 session 应失效 |
| **拉黑** | 可登录，但不能下单、不能下载 |

二者独立，可同时存在；列表用「是否拉黑」筛选，禁用为账号状态字段。

### 4.3 壁纸资源

#### 3.1 壁纸列表

状态（建议四态，便于筛驳回）：

```text
上传/保存 → 待审核
              ├─ 通过 → 已上架
              └─ 驳回 → 已驳回
已上架 → 下架 → 已下架
已下架 → 再上架需重新进入「待审核」
删除 = 软删（列表默认隐藏；R2 原图是否物理删除另定）
```

| 类型 | 能力 |
|------|------|
| 上传 | 单张上传、批量上传；入库默认为「待审核」 |
| 单条 | 审核通过、驳回（必填理由）、下架、编辑、删除 |
| 批量 | 批量审核通过、批量下架、批量修改分类、批量删除 |
| 原图 | 列表展示原图是否已传；**原图缺失时不可审核通过**（或通过时强校验） |

原图路径约定（与现网一致）：R2 `originals/{id}.jpg`。

#### 3.2 分类管理

新增、编辑、删除。数据供 **C 端筛选**。

#### 3.3 标签管理

新增、编辑、删除。数据供 **C 端筛选**。

#### 3.4 下载记录

只读为主：用户、壁纸、时间、当时会员档、是否成功。

### 4.4 订单财务

#### 4.1 全部订单

须包含：

- 正式付费订单（虎皮椒等）
- 0 元免费开通订单
- 后台手工开通 / 续费订单

行内 / 工具能力：

- 补发会员权限（已支付未到账时重放履约，打操作日志）
- 标记退款（是否同步收回会员权益需可确认）
- 查看支付回调原始日志
- 订单数据 Excel 导出对账

建议订单类型（筛选用）：

| type | 含义 |
|------|------|
| `paid` | 虎皮椒实付 |
| `free` | C 端免费档开通（0 元） |
| `admin_grant` | 后台手工开通 / 续费（0 元或填写金额） |
| `mock` | 开发模拟（生产可隐藏） |

#### 4.2 财务统计

## 5. 角色与权限（RBAC）

> 权限分三层：**菜单**（进不进页）、**按钮**（页内能不能点）、**数据**（能看谁的数据）。  
> 配置主要在「角色」；管理员可覆盖「数据权限」。

### 5.1 模型

```text
角色 Role
  ├─ menus[]     菜单权限（二级路由 key）
  ├─ buttons[]   页面按钮权限（action key）
  └─ dataScope   默认数据权限：all | self

管理员 Admin
  ├─ roleId      绑定一个角色 → 继承 menus + buttons
  └─ dataScope   follow_role | all | self（编辑管理员时可覆盖）
```

生效规则：

- `effectiveMenus` / `effectiveButtons` = 角色上的配置  
- `effectiveDataScope` = `admin.dataScope === 'follow_role' ? role.dataScope : admin.dataScope`

内置「超级管理员」角色：菜单/按钮全开，`dataScope=all`，不可删除；种子账号 `admin` 绑定该角色。

### 5.2 菜单权限

- 与侧栏二级菜单一一对应（叶子节点勾选）。
- 前端：无菜单则侧栏隐藏，直输 URL → 无权限页。
- 后端：对应模块 API 校验菜单 key（或模块前缀）。

建议 key（与路由对齐，实现时放 `packages/shared`）：

| key | 菜单 |
|-----|------|
| `dashboard.overview` | 数据总览 |
| `users.list` / `users.blacklist` | 用户列表 / 黑名单 |
| `wallpapers.list` / `categories` / `tags` / `downloads` | 壁纸资源 |
| `orders.list` / `finance` | 订单 / 财务 |
| `settings.admins` / `roles` | 员工管理 / 角色管理 |
| `tools.cloudflare` / `r2` / `resend` / `pay` / `audit` / `jobs` | 系统工具 |

### 5.3 页面按钮权限

按钮挂在**具体页面**下，角色配置里用树形展示：菜单 → 其子按钮。

命名：`{menuKey}.{action}`，例如：

| key | 含义 |
|-----|------|
| `wallpapers.list.upload` | 单张/批量上传 |
| `wallpapers.list.approve` | 审核通过 |
| `wallpapers.list.reject` | 驳回 |
| `wallpapers.list.unpublish` | 下架 |
| `wallpapers.list.edit` | 编辑 |
| `wallpapers.list.delete` | 删除 |
| `wallpapers.list.batch` | 批量操作 |
| `users.list.edit` | 编辑资料 |
| `users.list.disable` | 禁用/解封 |
| `users.list.renew` | 手动续费 |
| `users.list.logs` | 查看用户日志 |
| `orders.list.export` | 导出 |
| `orders.list.refund` | 标记退款 |
| `orders.list.regrant` | 补发权限 |
| `settings.admins.create` | 新增员工 |
| `settings.roles.create` | 新增角色 |
| … | 各页按行内/顶栏主操作补齐 |

约定：

1. **有菜单无按钮** → 可进页只读（适合审计角色）；列表仍受数据权限过滤。  
2. **勾选按钮默认要求已勾对应菜单**（UI 上未勾菜单则子按钮禁用）。  
3. 前端：`v-permission="'wallpapers.list.approve'"` 或等价 composable 控制显隐。  
4. 后端：**写操作 API 必须校验按钮权限**（不能只藏按钮）；读列表主要靠菜单 + 数据范围。

### 5.4 数据权限

| 值 | 含义 |
|----|------|
| `all` | 模块内全部数据 |
| `self` | 仅 `createdByAdminId === 当前管理员` 的数据 |

- 壁纸、公告、分类/标签变更、操作日志等：支持 `self`（写入时打创建人）。  
- 用户、订单、下载记录等无「个人归属」的：选了菜单则数据范围视为 `all`，配置 UI 可禁用 `self`。  
- 管理员编辑：**数据权限**可选「跟随角色 / 全部 / 仅个人」。

### 5.5 角色管理页（5.5）

| 能力 | 说明 |
|------|------|
| 列表 | 名称、标识、绑定员工数、更新时间 |
| 新增/编辑 | 名称、备注；菜单树 + 展开后的按钮勾选；默认数据权限 |
| 删除 | 仍有员工绑定则禁止；系统超管角色不可删 |

### 5.6 员工编辑（补充）

在 5.4 编辑中配置：

- 角色（决定菜单 + 按钮）  
- 数据权限覆盖（`follow_role` / `all` / `self`）

登录与 `/api/admin/auth/me` 返回：`menus`、`buttons`、`dataScope`，供前端侧栏与按钮使用。

## 6. 三类日志分工

| 名称 | 入口 | 记什么 |
|------|------|--------|
| 用户操作日志 | 2.1 行内 | 该用户：登录相关、禁用、拉黑、会员变更 |
| 下载记录 | 3.4 | C 端下载行为 |
| 全局操作日志 | 6.5 | 管理员：改配置、审壁纸、改订单、改用户权益等 |

手工改权益时至少落三处：`admin_grant` 订单、用户维度会员变更日志、全局操作日志。

## 7. 与 C 端耦合

1. 分类 / 标签 → 列表 API 支持筛选；删除前检查壁纸引用。
2. 仅「已上架」且原图就绪 → C 端展示与下载。
3. 档位与价目 → 下单与档位鉴权均读取 5.2 配置（替换当前 `packages/shared` 写死价目的长期方向）。
4. 用户详情 ↔ 订单列表可互跳；凡改权益必有订单行。

## 9. 明确不做（当前阶段不进菜单）

- 优惠券 / 邀请码
- 工单 / 用户反馈
- 专题 / Banner / 推荐位（除非 C 端已有对应位）
- 多语言、独立 SEO 专题页
- 物理回收站（以下架 + 软删标记代替即可）
- 按「每个菜单单独一套数据范围」的复杂矩阵（一期角色级默认 + 管理员覆盖即可）
